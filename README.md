# Ω Omega-Trader

**ربات معامله‌گر خودکار فارکس** با موتور تصمیم‌گیری ترکیبی (ensemble) روی شش خانواده‌ی اندیکاتور، مدیریت ریسک درصدی، و داشبورد وب زنده.

یک موتور، سه حالت اجرا: **بک‌تست**، **پیپر تریدینگ**، و **لایو روی MetaTrader 5**.

## ⚠️ قبل از هر چیز

این یک ابزار مهندسی‌شده است، نه یک ماشین پول‌سازی. سه نکته‌ای که باید بپذیری:

1. **هیچ ربات معامله‌گری سود تضمینی ندارد.** این کد تصمیم‌گیری را منظم و بدون احساسات می‌کند؛ «لبه‌ی بازار» (edge) را از هوا نمی‌سازد.
2. **داده‌ی پیش‌فرض مصنوعی است.** برای تست کل سیستم عالی است، برای قضاوت درباره‌ی سودآوری بی‌ارزش. با داده‌ی واقعی بروکر خودت بک‌تست بگیر.
3. **مسیر درست:** بک‌تست ← پیپر حداقل ۱ تا ۳ ماه ← حساب دمو ← حساب واقعی کوچک. حالت لایو عمداً پشت دو قفل است.

## ۳. موتور تصمیم‌گیری

شش «بلوک رأی‌دهنده» مستقل، هر کدام بازار را در بازه‌ی `[-1, +1]` امتیاز می‌دهند:

| بلوک | چه می‌خواند | وزن پایه |
|---|---|---|
| `trend` | EMA 21/55/200، ADX و ±DI، Supertrend، Parabolic SAR، شیب رگرسیون خطی | ۱٫۰۰ |
| `momentum` | RSI، Stochastic، MACD، CCI، ROC، Williams %R، واگرایی RSI | ۰٫۹۰ |
| `volatility` | Bollinger %B، شکست Keltner، Squeeze، صدک ATR | ۰٫۶۰ |
| `volume` | MFI، Chaikin Money Flow، شیب OBV، Force Index، حجم نسبی | ۰٫۵۰ |
| `structure` | ساختار سوئینگ‌ها، شکست Donchian، عمق پولبک، الگوی کندل | ۰٫۸۰ |
| `htf_bias` | همین تحلیل روی تایم‌فریم بالاتر (پیش‌فرض H4) | ۱٫۰۰ |

### نکته‌ی کلیدی: وزن‌ها ثابت نیستند

سیستم اول **رژیم بازار** را تشخیص می‌دهد (`TREND_UP`، `TREND_DOWN`، `RANGE`، `VOLATILE`، `QUIET`) و بعد وزن‌ها را بازتنظیم می‌کند:

- در **روند**: بلوک trend ×۱٫۳۵، نوسان‌نماها ساکت‌تر، و اسیلاتورها **هم‌جهت روند** خوانده می‌شوند.
- در **رِنج**: بلوک momentum ×۱٫۳، و همان اسیلاتورها **برعکس** تفسیر می‌شوند (RSI بالای ۷۰ یعنی سیگنال فروش، نه خرید).

این تفاوت بین یک ربات حرفه‌ای و یک «EMA cross» ساده است.

### شرایط ورود

معامله فقط وقتی باز می‌شود که **همه‌ی** این‌ها برقرار باشد:

</div>

```
|score| ≥ entry_threshold            (پیش‌فرض ۰٫۲۸)
confidence ≥ min_confidence          (پیش‌فرض ۰٫۴۵)
تعداد بلوک‌های هم‌نظر ≥ 3
تایم‌فریم بالاتر مخالف نباشد
داخل سشن معاملاتی مجاز
اسپرد زیر سقف تعیین‌شده
هیچ وتوی مدیریت ریسک فعال نباشد
```

## ۴. مدیریت ریسک

مهم‌ترین بخش پروژه. **تنظیم درصد ریسک** دقیقاً همان چیزی است که خواستی:

</div>

```yaml
risk:
  risk_per_trade_pct: 1.0      # ◀ درصد اکوئیتی که بین ورود تا حد ضرر ریسک می‌شود
```

<div dir="rtl">

### حجم پوزیشن چطور حساب می‌شود؟

حجم **مشتق** می‌شود، حدس زده نمی‌شود:

</div>

```
پول در معرض ریسک = اکوئیتی × risk_per_trade_pct / 100
ضرر هر لات       = فاصله‌ی حد ضرر / tick_size × tick_value
حجم (lot)        = پول در معرض ریسک / (ضرر هر لات + کمیسیون)
```

<div dir="rtl">

یعنی حد ضرر پهن → حجم کوچک، حد ضرر تنگ → حجم بزرگ، و **پولی که ریسک می‌کنی همیشه ثابت می‌ماند**.

> مثال واقعی از خروجی تست: حساب ۱۰٬۰۰۰ دلار، ریسک ۱٪، حد ضرر ۲۰ پیپ روی EURUSD → دقیقاً **۰٫۵۰ لات** و **۱۰۰ دلار** در معرض ریسک.

### لایه‌های محافظ

| پارامتر | کار |
|---|---|
| `risk_per_trade_pct` | ریسک هر معامله (اهرم اصلی) |
| `scale_risk_with_confidence` | ریسک متناسب با اطمینان سیگنال، بین ×۰٫۵ تا ×۱٫۲۵ |
| `max_total_risk_pct` | سقف مجموع ریسک همه‌ی پوزیشن‌های باز |
| `max_open_positions` / `max_positions_per_symbol` | سقف تعداد پوزیشن |
| `max_currency_exposure` | سقف تمرکز روی یک ارز (مثلاً حداکثر ۲ معامله‌ی درگیر USD) |
| `max_daily_loss_pct` | توقف معاملات تا پایان روز |
| `max_weekly_loss_pct` | توقف تا پایان هفته |
| `max_drawdown_pct` | **کلید قطع اضطراری** از سقف اکوئیتی |
| `max_consecutive_losses` + `cooldown_minutes_after_streak` | استراحت اجباری بعد از ضررهای پیاپی |
| `reduce_risk_after_loss` | کاهش خودکار حجم در دوره‌ی ضرر (پیش‌فرض ×۰٫۶) |
| `min_free_margin_pct` | کف مارجین آزاد |

### مدیریت معامله‌ی باز

- **حد ضرر**: `atr` (ضریبی از ATR) | `fixed_pips` | `structure` (پشت آخرین سوئینگ تأییدشده)
- **سر به سر**: انتقال حد ضرر به نقطه‌ی ورود در `+1R`
- **تریلینگ**: Chandelier روی سقف/کف ثبت‌شده — **فقط به نفع معامله حرکت می‌کند، هرگز شل نمی‌شود**
- **خروج پلکانی**: بستن نصف پوزیشن در `+1.5R`
- **خروج سیگنالی**: وقتی تز معاملاتی تضعیف شد — اما فقط بعد از `+0.6R` سود

</div>

> 💡 چرا `exit_min_r`؟ بدون آن، ربات با هر نوسان کوچکِ امتیاز در سود ناچیز خارج می‌شود و ضررها را کامل می‌خورد — یعنی دقیقاً برعکس «جلوی ضرر را بگیر، بگذار سود بدود».

## ۵. صداقت بک‌تست

بی‌فایده‌ترین چیز دنیا، بک‌تستی است که دروغ می‌گوید. این موتور عمداً بدبین است:

| موضوع | رفتار سیستم |
|---|---|
| زمان پر شدن سفارش | تصمیم روی **بسته‌شدن** کندل، اجرا روی **باز شدن کندل بعدی** |
| اسپرد | خرید روی Ask، فروش روی Bid — رفت و برگشت هزینه دارد |
| اسلیپیج | قابل تنظیم، همیشه **به ضرر** تو |
| کمیسیون | به ازای هر لات، رفت و برگشت |
| سواپ | محاسبه‌ی شبانه، سه‌برابر چهارشنبه‌ها |
| کندل مبهم | اگر کندلی هم حد ضرر و هم حد سود را لمس کرده باشد، **حد ضرر** فرض می‌شود |
| مارجین | سفارش بدون مارجین کافی رد می‌شود |
| look-ahead | با تست خودکار تضمین شده (پایین را ببین) |

## ۱۱. تنظیم برای بازار خودت

| هدف | چه کنی |
|---|---|
| معاملات کمتر ولی با کیفیت بالاتر | `entry_threshold` ↑ ، `min_agreeing_blocks` را ۴ کن |
| ربات زیادی محافظه‌کار است | `entry_threshold` ↓ ، `require_htf_alignment: false` |
| ضررها خیلی بزرگ‌اند | `atr_stop_mult` ↓ یا `risk_per_trade_pct` ↓ |
| سودها خیلی زود بسته می‌شوند | `exit_min_r` ↑ ، `trail_atr_mult` ↑ ، `partial_tp_r` ↑ |
| اسکالپ کوتاه‌مدت | `timeframe: M5` + `htf_timeframe: H1` + اسپرد سخت‌گیرانه |
| سوئینگ بلندمدت | `timeframe: H1` + `htf_timeframe: D1` + `atr_stop_mult: 2.5` |

</div>

> ⚠️ **تله‌ی بهینه‌سازی:** `omega optimize` خیلی راحت پارامترهایی پیدا می‌کند که روی داده‌ی گذشته عالی‌اند و در آینده شکست می‌خورند. همیشه برنده را روی بازه‌ی زمانی‌ای که در بهینه‌سازی نبوده دوباره تست کن.
